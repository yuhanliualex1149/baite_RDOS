# RDOS Skill 1.2.1：有界检查与当轮数据复用

共享表中的跨项目回执会经 `scope → task → read_rows` 重读任务表；互派任务经 `_peer_registry` 再读协作记录。每个本节点任务的 prepare/checkpoint 又重复这一过程。40 条任务、116 条事件的离线诊断复现了 200 次全表读取、98 次登记请求和 3,038 次签名调用。

本次在原正式源码修复，不改变业务协议 v2、任务规则或检查点结构：

- check/connection 在任何任务处理或自动 ACK 前完整读取两表；当轮共用原始行、解析结果、任务/回执索引及已验证登记。
- 登记从原始事件行构建，避免解析事件时再次进入任务/登记读取；先排除与本节点无关的互派任务。相同公钥、正文、签名的验证结果当轮复用，登记过期仍逐次检查。
- 自动 ACK 的独立读回保留；发生写入后刷新事件快照，清除依赖旧登记的解析结果及索引。下一轮和独立 prepare/submit/verify 重新读取。
- 两个命令支持 `--timeout-seconds`，默认 120 秒。共享单调时钟预算覆盖 CLI、Node 签名、下载、SQLite 写锁和检查循环；超时直接报告 check_timeout 及阶段，不能被隔离或恢复路径吞掉。
- 发布版本与能力回执为 1.2.1；中央和新版节点同时接受既有版本及 1.2.1。

新增回归覆盖调用次数、跨项目互派、签名篡改、登记过期、连续检查新鲜度、自动 ACK 刷新、远端独立读回及超时传播，并加入现有发布回归入口。

候选定向回归 86 项通过。同一真实数据的候选离线回放为两次全表读取、一次登记构建、31 次实际签名进程、2.417 秒；旧版回放为 200 次全表读取、98 次登记请求、3,038 次签名调用。旧版诊断额外复用了签名结果以限制诊断用时，不能用两个离线耗时比较真实线上耗时。

完整回归、Linux 构建、正式发布及本机升级证据单独保存在本轮发布记录，不能用此说明推定已经上线。
