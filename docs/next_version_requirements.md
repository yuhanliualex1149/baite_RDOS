# RDOS 下一版需求清单

## NEXT-001：配置 Runner 节点后直接提供 Agent onboarding 指令

- 记录日期：2026-09-29
- 状态：候选实现中；正式发布与 WorkBuddy 实机验收待完成
- 目标版本：下一版 Panel，面向其他伙伴开放使用前
- 需求来源：用户确认

### 要解决的问题

管理员配置节点后，伙伴不应再手动重复安装、配置和验证 Runner 的整套操作。Panel 应直接提供可复制给 WorkBuddy 或其他本地 Agent 的明确接入指令，由 Agent 完成后续配置与验证。

### 预期流程

1. 管理员在 Panel 创建或配置伙伴的独立 Runner 节点，并按需分配项目。
2. 配置完成页面直接显示该节点的 onboarding 指令，提供“复制接入指令”和现有的配置文件下载入口。
3. 管理员将指令与该伙伴专属配置安全交付；伙伴把配置保存到本地，再将指令交给自己的 Agent。
4. Agent 读取在线 onboarding 文档，检查本机环境、确定 Workspace、安装或复用匹配版本的 Runner、完成配置与启动。
5. Agent 验证同步和一次测试事件的 ACK，报告实际结果；遇到系统授权或管理员权限问题时，只请求必要的人工操作。

### 指令与安全边界

- 指令包含服务地址、节点 ID、配置文件使用方法、在线文档链接、Agent 执行步骤和验收标准。
- 不在公共文档或可转发指令中嵌入 Runner Token、管理员密码；凭证仅通过个人专属配置文件交付。
- 不把管理员身份交给伙伴的 Agent；创建节点、调整项目权限等操作仍由管理员完成。
- 每个伙伴使用独立节点与凭证；同一 Workspace 不重复启动 Runner。
- 复用已有配置和 Workspace 时保留历史文件，不擅自清空数据、轮换 Token 或新建重复节点。
- 不硬编码开发者目录、真人姓名或单一操作系统的安装命令；遇到不支持的系统应明确说明。
- 保持“Panel 管协作、Runner 管同步、Local Agent 管具体工作”，onboarding 只处理接入，不规定研发执行方式。

### 验收标准

- 管理员完成节点配置后，可直接复制对应节点的接入指令，不需要另写操作教程。
- 伙伴只需提供自己的配置文件、指令和必要的系统授权，Agent 可完成受支持环境的安装与配置。
- 复用已有有效节点时不要求重新注册；失败时能明确区分本地环境、凭证、文档访问和网络问题。
- 成功验收包括：节点 Online、共享资料同步成功、测试事件收到 ACK；未验证的项目不得标记完成。
- 无凭证泄露、跨节点混用或重复 Runner 进程。
